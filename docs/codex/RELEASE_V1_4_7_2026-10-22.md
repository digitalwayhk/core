# Core v1.4.7：普通WS中继兼容与compress安全补丁

本补丁基于v1.4.6发布提交`797781f01bb618f70fbc8ca47afc164a2a1cbd49`。仅修改Core，未读取、修改、升级或部署Bitzoom/Full-E4。保留既有前端研究WIP，未修改前端产物。用户已授权正式补丁发布。

## 根因和最小修复

v1.4.6的`ServiceContext.HandleInternalPayload`在原`invokePayload`之前调用`handleOwnedWebSocketRelay`。后者识别两个精确路径后，对没有`IWebSocketOwnedReference`的目标返回`handled=true, ownership.ErrUnsupported`。因此普通Public/Private WS即使登录和订阅ACK成功、正式中继也已注册，摘要仍无法更新远端索引，notice也无法进入原处理器。RPC失败可进一步触发客户端熔断；本地复现证明该分支故障，不量化现场所有等待时间或将全部超时归于它。

修复保留同服务可信mTLS、SAN/SourceService一致、服务准入、1MiB边界、目标存在和摘要节点服务归属校验。只有完成这些检查、目标又没有可选归属接口时返回`handled=false`，继续`invokePayload → dispatchLocal → 已注册SyncSubscription/ForwardNotice`。前者真正调用现有Broker更新索引，后者真正调用`ExecuteLocalNotice`投递；没有吞错或伪造成功。归属路由继续原内建分支，Ready owner、SQL fence、引用恢复及退订机制不变。

自审额外发现两项边界问题并先保留RED：已注册旧中继的`WithAuth(false)`让HTTP绕开gRPC检查；同服务mTLS还能通过通用入站分发调用实际注册的`getmenu`。两个正式中继的Validation现在要求框架可信同服务身份；`HandleInternalPayload`只为两个精确WS中继放行ServerManage特例，拒绝其它ServerManage路径。用户/管理Token、自报HTTP头、匿名、异服务证书都不建立这种身份。管理HTTP认证域不变。

修改生产函数：

| 文件 | 函数 | 变化 |
| --- | --- | --- |
| `pkg/server/router/owned_websocket_relay.go` | `handleOwnedWebSocketRelay`、私有`isWebSocketRelayPath` | 共享校验在前，普通路由继续正式分发；归属分支保留 |
| `pkg/server/router/servicecontext.go` | `HandleInternalPayload` | 仅两个精确WS路径获得ServerManage内部例外 |
| `pkg/server/api/manage/noticerelay.go` | 两个`Validation`、私有`validateWebSocketRelayCaller` | HTTP/用户Token不能绕过可信服务边界 |
| `go.mod`、`go.sum` | compress版本选择 | v1.18.6 → v1.18.7，其它依赖不变 |

没有新增可选开关、公开Go方法、业务字段、第二套转发器、MQ消费者或后台worker。

## compress安全修复

[上游公告GHSA-259r-337f-4rfw](https://github.com/advisories/GHSA-259r-337f-4rfw)将S2字典repeat整数溢出及后续越界编码列为High/CVE-2026-63209，修复版本v1.18.7。已用实际`s2.NewDict`复现旧版错误接受溢出字典，升级后拒绝，同时保留有效字典。测试不执行危险Encode。`internal/compat`最低安全版本与行为回归已纳入`scripts/test.sh security`，防止整理依赖时降回旧版。`go list -m`确认实际选择v1.18.7，无replace。

该结果只覆盖此公告和本次回归，不宣称所有依赖公告已消除，也不以GitHub告警页面同步状态代替模块选择。

## 消费方升级

```bash
go get github.com/digitalwayhk/core@v1.4.7
go list -m github.com/digitalwayhk/core github.com/klauspost/compress
```

普通WS保持原路由、原身份/Hash/过滤器及正式两个中继注册，不要伪造`IWebSocketOwnedReference`。典型注册为`sc.Router.AddServerRouters(&manage.SyncSubscription{}, &manage.ForwardNotice{})`，并使用已支持的同逻辑服务可信mTLS内部gRPC；证书SAN须匹配SourceService，节点注册须与该逻辑服务一致。未注册普通中继时仍返回错误。

两个旧中继的HTTP调用现在返回403，用户或ServerManage Token不能替代服务身份；仅凭网络ACL、匿名HTTP或内部gRPC直接调用其它ServerManage的旧用法须改回对应认证域的HTTP管理入口。此安全收紧已登记兼容面与skill。普通对外Public/Private HTTP/WS身份和管理HTTP协议不变。

不删除或重建Stream、消费组、PEL、游标、SQL fence、引用或业务消息；不改变原Ownership Manifest和Provision/Bind流程。重启Gateway后客户端按原协议重连/订阅；仍存活会话的归属免重订恢复继续适用。无需清数据或给普通路由新增归属声明。Core未替任何消费方执行升级命令。
