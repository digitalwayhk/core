# Core v1.6.0：显式仅Broker可靠消费

## 版本与变更

基线 v1.5.0 / `d73f9af45d21740ae48514d969cd01b31321ee0a`。新增公开订阅选项与可选能力接口，按仓库SemVer发布MINOR v1.6.0；正式提交以annotated tag和GitHub Release为准，不改写旧tag。

实现提交 `897c66c1ab2b78b2abab156350aa8de271907af7`；原始验收/文档提交 `f41211b5647a3ddf98270db50d3e92baa676a845`。本次发布只补版本、兼容与合并说明，生产源码与已验证的8个Go文件指纹一致。

旧可靠订阅在本地发布阶段同步执行，也在Broker入站执行。新增 `event.Subscription.BrokerOnly=true` 后，只有外部可靠入站执行该handler，包括本服务Source；Outbox可在Broker接受后确认，不等待该投影事务完成。默认false继续原交付，其他默认handler和Outbox跨批屏障不变。

同主题新旧handler复用一个实际组订阅，仍须全部匹配handler完成才ACK；显式校验可靠能力、有效Subject、逻辑组和同一Stream接线。修正取消身份，协调在途可靠handler与Close，不把迟到nil当ACK成功。没有修改Redis Provider、消息生命周期、Outbox算法、业务模型或依赖。

## 消费方升级

```bash
go get github.com/digitalwayhk/core@v1.6.0
```

只在需要异步Broker消费的原订阅中增加 `BrokerOnly:true`，继续原 `ServiceContext.SubscribeEvent`、handler、Subject/EventType、SharedKeys/Prefetch、幂等和事务。新模式MQ off/能力或接线不足明确返回错误，应用在Initialize传播，不另写worker或双套订阅。

不需要改历史消息、分组、pending或游标，禁止清数据升级。滚动混跑期间旧节点仍会同步本地交付，不能宣称全服务立即解耦。发布确认不是消费ACK，重复仍由原Inbox/业务事务幂等收敛；接管不是业务APPLIED。新模式不自动给无预算的旧消费者添加有限重试。

继承v1.5.0已启用write-behind持久状态的应用，仍须遵守该模式禁止旧二进制直接打开新卷的边界。本轮没有改变该状态或回滚合同。
