# v1.4.2：Redis 可靠订阅跨读取窗口修复

本补丁在 v1.4.1 / `60791a7` 上合入修复 `65806a2`。慢 key 不再使可靠订阅读取循环等待整批完成：B1 完成后，可利用空闲 worker 处理下一窗口 B2，同时保留 A 的失败屏障。公开 API、消息编码、依赖及已有内嵌前端产物不变；不会修改消费方业务代码、清空消息或重置消费组。

## 修复内容

- Redis 显式 `KeyConcurrency>1` 使用 owner 会话级固定 worker，替代同步批次末尾的 `wg.Wait()`；每 key 仅准入最早未完成消息，同 key 串行，不同 key 有界并行。
- owner 续约与抢占分离，读取/认领及可靠 ACK/DLQ 分别原子校验 owner；失主工作不能重新抢占租约后 ACK。ACK 响应丢失时，重试前复核 PEL，避免本地失败 work 异常重放已 ACK 消息。
- 分 key 超时/取消后等待原 handler 真正退出，避免同 key 重试重叠和 handler goroutine 持续累加。Go 不能强杀业务 handler；不合作的 handler 仍会占住有限 worker 并延迟 `Close`。
- 新增发布、读取、PEL、调度和 handler 的 OTel 时钟，通过 stream hash + Redis message ID 关联，消费侧另带 group hash；补齐固定指标白名单。正文、原始 OrderingKey、业务幂等 ID、token、DSN 和业务 error 正文不写入新增观测，消息/订单/用户标识不成为指标标签。

## 消费方升级

```bash
go get github.com/digitalwayhk/core@v1.4.2
```

Core 根 `go.mod` 声明模块名，本身不设置自身发布版本；本补丁不升级第三方依赖，也不修改消费方 `go.mod`。项目使用新版本后重新运行 `scripts/link-consumer-skill.sh`，阅读更新后的权威 skill 和本节行为边界。

1. 继续使用正式可靠订阅入口、稳定 OrderingKey 和显式 `KeyConcurrency`；零值/1 继续整 subject 串行。
2. Redis 分 key 的有效窗口 W=`max(Count,KeyConcurrency)`；`Count<=0` 时补为 `4*KeyConcurrency`。W 同时约束分页、跟踪 work 和本 owner 新预取的 PEL，还受较小的 `Retry.MaxAckPending` 限制。满预算时背压新读取，已有超限 PEL 只分页恢复；有限预取不承诺穿过任意多热 key 消息找到后方 key。
3. 可靠 handler 应在持久化成功后返回 nil，由 provider ACK；移除手动提前调用 `Message.Ack` 的代码。失败、取消、未知结果不得当作成功，继续保留 Inbox/业务幂等与事务约束。
4. 对数据库/HTTP 等业务 I/O 设置有效超时。分 key 模式现在等待超时 handler 实际退出，不用替代 goroutine 绕过它；串行分支及 NATS 的既有超时实现未在本补丁改为同样的退出等待保证。
5. 同组 Consumer 仍须使用唯一实例身份。建议先停止旧订阅并等待 handler 退出，再部署新版本，保留原消息和 PEL；新旧版本同组混跑未验收。

`pending_keys` 表示本地跟踪 key 数，`prefetched_messages` 表示组 PEL 消息数，不能互相替代。接管前首次读取未知时，观测标记 `first_read_known=false`，不补造历史时钟。精确指标口径、文件/函数清单和原始命令见[完整修复验收](REDIS_RELIABLE_CROSS_WINDOW_FIX_2026-10-20.md)。从 v1.3.0 或更早版本升级时，还须同时执行[既有迁移指导](UPGRADE_FROM_V1_3.md)。

- 修复阶段：真实 Redis 7.4.11 的 RED→GREEN，包括下一读取窗口、PEL 后页及正式 `MQBridge → PublishControl → 已注册 handler` 链。三包普通回归和 race 各 207 条 PASS 记录；十轮真实 Redis/race 重复验证 200 条 PASS 记录；`go vet` 通过。计数包含父测试和子用例。
- 26 条 skip 记录中，25 条为未配置 NATS 的用例，1 条为仅由子进程执行的崩溃 fixture 入口；实际子进程 `os.Exit(73)` 后的恢复测试已运行，只加速该崩溃 owner 的 TTL 到期，没有删除消息。
- 发布前运行 `scripts/test.sh release-contract`、`CORE_RELEASE_VERSION=v1.4.2 scripts/release-check.sh --release`、`web-dist-sync` 和嵌入前端测试。使用本轮干净检出，避免未跟踪的前端研究文件进入模块；Go 源码及根依赖与已验收修复提交逐字绑定。精确日志封存于本地 `.temp/release-v142/`。
