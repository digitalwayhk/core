# v1.4.3：OpenAPI 依赖安全升级

本版基于 v1.4.2 / `ed36f79`，仅升级两个依赖、增加安全回归及门禁，并更新发布文档。`kin-openapi v0.144.0 → v0.149.0`，其间接依赖 `jsonschema/v6 v6.0.2 → v6.0.3`。不修改 Core 生产 Go 代码、认证域、公开签名、Redis 调度或已提交的内嵌前端。

## RED、GREEN 与回归命令

新增用例在 `pkg/server/internal/openapiutil/dependency_security_test.go`，五组入口为 `TestOpenAPIDependency*`。先使用旧版本真实运行，五组均失败：空指针、编码路径穿透和子进程 fatal stack overflow 均被捕获。最终测试再用 v1.4.2 的原始 go.mod/go.sum 通过 `-modfile` 复跑，确认五组仍为 RED；新依赖五组均为 GREEN。递归子进程栈限制为 1 MiB，10 秒超时，不让旧版本耗尽宿主栈。

```bash
GOWORK=off go test ./pkg/server/internal/openapiutil -run TestOpenAPIDependency -count=1 -v -timeout=90s
GOWORK=off go test ./pkg/server/internal/openapiutil ./pkg/server/internal/openapidoc ./pkg/server/run ./internal/compat -count=1 -timeout=5m
GOWORK=off go test -race ./pkg/server/internal/openapiutil ./pkg/server/internal/openapidoc ./pkg/server/run ./internal/compat -count=1 -timeout=5m
GOWORK=off go vet ./pkg/server/internal/openapiutil ./pkg/server/internal/openapidoc ./pkg/server/run ./internal/compat
bash scripts/test.sh release-contract
CORE_RELEASE_VERSION=v1.4.3 bash scripts/release-check.sh --release
bash scripts/test.sh web-dist-sync
```

精确执行日志与结果保存在本地 `.temp/release-v143/`：`security-RED-final.log`、`security-GREEN.log`、`targeted-checks.json` 及正式发布检查记录。夹具初次缺少可选 router 依赖的 setup 失败、初次对无约束表单错误要求 400 的断言失败均另行保留，不算安全 RED；最终用 Core 已有的 legacy router，不新增路由库依赖。

## 消费方升级与边界

```bash
go get github.com/digitalwayhk/core@v1.4.3
```

标准 Core 服务仅使用 OpenAPI 类型、生成和兼容工具；本轮检查未见生产链调用 `openapi3filter`、`VisitJSON` 或 `ValidationHandler`。依赖安全测试显式调用这些入口，用于防止后续降级；测试通过不表示过去的标准 Core API 可直接触发所有漏洞。

自行接入过滤器的消费方需要复测编码斜杠、公共/受保护路径重叠和自定义鉴权函数。query/deepObject 数组缺 items 返回正常解码错误；OAS 3.1 无约束组合表单允许被接受，安全契约为不崩溃，不能统一当成错误。递归 allOf 两条已验证路径不代表所有组合、合法递归数据约束或所有自定义解码器已穷举。

Core 文档生成继续使用 OAS 3.0.1；不引入新的运行时过滤中间件。HTTP 文档、路由、兼容快照、race、公开 API 及发布门禁通过后才创建新 tag。发布后另从官方代理下载 v1.4.3，核对来源提交、锁定依赖、已提交 Go 文件与内嵌资源，并运行无 replace 的独立消费方 smoke。普通 Go 消费方不需要拉取前端子模块源码。

本轮不修改、升级、重启或部署 Bitzoom，不进行其业务回归、存量数据迁移或性能压测；这些仍为 `NOT_RUN`。跨版本升级需继续遵守 [v1.4.2 行为边界](RELEASE_V1_4_2_2026-10-20.md)和[从 v1.3.0 升级指导](UPGRADE_FROM_V1_3.md)。回退到 v1.4.2 会重新引入上述旧依赖；不得移动已发布 tag。
