# v1.7.0 PostgreSQL 支持发布说明

## 范围与版本

本次为 PostgreSQL 加性存储能力，按 MINOR 发布。功能提交为 `c564495`；整合主线 `67494cfd99f34fbc571d3d5e3eebb0b53f3210d9`，保留 v1.6.4 及之前修复。最终提交由 annotated tag 固定，不改写已有标签。

PostgreSQL 只在模型组合根显式设置 `Driver=postgres` 或调用 `NewPostgres` 时启用；Core 控制面独立设置 `server.json.ManageStore.Driver`。新安装默认 SQLite `core_manage`，未声明 ManageStore 的旧配置仍读取 SQLite `models.db`。07 未声明驱动时保留旧 MySQL 构造与其 DSN 支持的配置。切换数据库不会搬迁历史数据。

## 升级与回退

- 现有服务继续使用原数据库配置；需要 PostgreSQL 时先准备权限、TLS、备份及历史数据处理，在启动阶段、接受请求前运行模型组合根 `EnsureStorage()`。框架只自动执行加性初始化，不自动改旧列类型或删除旧列。
- 未开启 PostgreSQL 也会使用更新后的共享查询与聚合代码。SQLite 周桶从 `%Y-W%W` 改为 ISO 周年，例如 `2021-01-01` 从 `2021-W00` 改为 `2020-W53`；检查历史快照、跨年报表及刷新范围。
- 旧显式统计方言与实际连接不一致时报错，未知驱动不再回退 MySQL。MySQL ManageStore 的连接最大生命周期从不限变为30分钟，升级时关注连接回收。
- 07 旧 MySQL 路径直接保留 `remoteMySQLConfig()`，防止通用配置转换丢失 `Charset`、`Loc` 和主线新增的 `InterpolateParams`。参数化调用不变，原生 SQL 正文不自动翻译。
- 消费方固定正式标签后，重新执行 `scripts/link-consumer-skill.sh` 刷新权威 skill；`go get` 不自动更新副本或旧模块路径链接。
- 未切换数据库时可锁回 `v1.6.4` 并执行消费方 smoke；已切换者需保留原库和数据同步/回退方案，不得把回退代码等同于 PostgreSQL 数据自动回迁。
