# v1.4.6：跨主题持续归属与恢复

## 版本与范围

按用户指定发布v1.4.6，基线为v1.4.5 / `cdf3887b80f749683d42c6dda1f139fce1695d1c`。本次为显式启用的加性能力，不更改原零值订阅、消息payload、EventID、ShardKey、原逻辑组/PEL/游标，不重做v1.4.4分担机制或v1.4.5连接池。

输入为《Core市场归属G0交付要求》，SHA256 `7edd6ba039ae986ba7cd295f4cd8d6827b972ad99909948ec99505afabf0e6ae`。准备材料内原“不授权Core修改”的说明由用户本轮直接实施请求覆盖；没有授权Bitzoom接入、G1–G5、部署、Full-E4或现场数据清理。本仓库禁止子Agent，所有实现/测试/审查由主Agent完成，不宣称独立审计。

## 修改及职责

- `pkg/server/ownership`：持续凭据、正epoch、应用SQL事务fence、待办/确认进度、引用快照视图、有限worker、实际退出等待与时限。
- `pkg/server/mq/ownership_contract.go`、`manager_ownership.go`：能力校验、显式Provision/Bind/Unbind/Recover、生命周期门禁。NATS和无MQ拒绝。现有有限次DLQ不具备整批语义，明确拒绝 `MaxDeliveries>0`。
- `provider_redis_ownership*.go`：原组有界PEL+新读取、同原OrderingKey连续前缀、跨主题同scope/key批次、持续租约与原子fenced ACK、正序列、Gateway版本快照。复用原命令池，不新增每订阅client。
- `event/owned_subscription.go`、`mqbridge_owned.go`：ServiceEventBridge/MQBridge正式批量入口；Envelope身份和业务数据不变。
- `router/owned_events.go`、`owned_service.go`、`request_owned.go`、`serviceresolver.go`：ServiceContext生命周期、Ready精确实例调用、原权限和返回后校验；多scope低基数指标汇总。
- `melody/ownership_*.go`、SessionSubscriptions生命周期：从现有会话自动生成有界版本快照、退订收敛和租约失效后原会话恢复。`router/owned_websocket_relay.go`只接通显式归属WS的两个精确内部gRPC中继，要求同逻辑服务可信mTLS，不开放匿名HTTP或其它管理接口。
- 新 `examples/11-scoped-event-ownership` 与四进程集成测试，包含真实MySQL fence、同事务去重/计数、mTLS内部查询及现有WS通知。

根因、准确调用链、预算与升级操作见 [运行指南](SCOPED_EVENT_OWNERSHIP_GUIDE.md)；接线必须读 [当前skill](../ai/core-skill/scoped-ownership.md)。

## 升级及未验证边界

```bash
go get github.com/digitalwayhk/core@v1.4.6
```

仅升级依赖不会自动把原SharedKeys变成持续归属；选择新能力须维护绑定并签收SQL fence、键目录/槽位、Due合同、原事件兼容和WS恢复。NATS明确不支持本合同；静态manifest不支持在线增删key/改W/Selector或Provider切换，没有自动均衡搬迁。新批次合同不支持有限次DLQ，不能为了启用而擅改消费方策略。原生命周期容量门禁保留，不把message lifecycle capacity reached当单owner或连接池问题。

NOT_RUN：生产Redis HA/持久化快照整体回退及磁盘恢复、SQL网络COMMIT响应真实丢包、任意远端业务调用fencing、生产容量/长稳压测、Bitzoom升级/G1–G5/UAT/部署。单进程双SQL连接证明行锁行为，独立处理PID证明分担，两者不得合并描述为已经完成所有生产故障组合。Core交付不替代消费方签收。
